# V0: Module-Level Camera Surface

V0 is the contract for the current `0.1.x-alpha` releases. It is what an app
can rely on **today**, before the `camera-view` native element exists. The
target contract for the native view is [V1.md](V1.md); milestone status lives
in [ROADMAP.md](ROADMAP.md).

V0 exists so a host app (for example a photo-upload flow) can ship real photo
capture now, then move to V1 without changing app-facing code: everything is
consumed through the same `CameraAdapter` surface that V1 will implement.

## What V0 Guarantees

### JavaScript surface

From `@kealanau/lynx-camera`:

- `createCameraAdapter(options)` — returns a `CameraAdapter` backed by the
  native module when registered, the mock when `{ mock: true }`, or `null`.
- `createNativeCameraAdapter(nativeModule)` — wraps an already-resolved
  native module.
- `getNativeCameraModule(name?)` — raw `NativeModules` lookup, `null` outside
  Lynx.
- Install checks: `getCameraInstallStatus`, `getCameraInstallStatusAsync`,
  `assertCameraInstalled`, `assertCameraInstalledAsync`, and
  `LYNX_CAMERA_JS_VERSION`.

From `@kealanau/lynx-camera/mock`: `createMockCameraModule`,
`defaultMockDevices`. From `@kealanau/lynx-camera/fixtures`:
`SAMPLE_PHOTO_FIXTURE`.

Authoritative types live in [`src/types.ts`](src/types.ts).

### Adapter behavior on iOS

- `getPermissions()`, `requestCameraPermission()`,
  `requestMicrophonePermission()` — real AVFoundation permission states,
  normalized to `PermissionStatus`.
- `getAvailableCameraDevices()` / `getDefaultCamera(position)` — real device
  enumeration normalized to `CameraDevice`.
- `capturePhoto(options?)` — presents the **system camera UI**
  (`UIImagePickerController`) and resolves with a `PhotoFile` whose image data
  is returned as `base64` with a `memory://lynx-camera/capture.jpg`
  pseudo-path. User cancellation rejects with code `capture/cancelled`.
- `startRecording`, `stopRecording`, `focusAtPoint`, `setZoom`, `setTorch` —
  **reject** with "not available yet" errors. They are V1 (view-session)
  features.

### Install checks

`getCameraInstallStatus()` distinguishes, with stable codes:

- `mock` — running intentionally against the mock adapter.
- `installed` — native module registered with all required methods.
- `native-modules-missing` — not a Lynx runtime (or `NativeModules` absent).
- `native-module-missing` — Lynx runtime, but `CameraModule` not registered.
- `native-methods-missing` — registered but stale/incomplete native source.
- `native-version-mismatch` — async check only; native
  `getLynxCameraNativeVersion()` disagrees with `LYNX_CAMERA_JS_VERSION`.

### Versioning rule

`package.json` `version`, `LYNX_CAMERA_JS_VERSION` in `src/native.ts`, and
`nativeVersion` in `ios/LynxCameraModule.swift` must be bumped together. The
test suite enforces this.

### Error shape

Native failures reject as `Error` whose message comes from the native
`{ error: { code, message } }` payload (message preferred, then code). Known
V0 native error codes: `camera/unavailable`, `camera/no-presenter`,
`capture/encode-failed`, `capture/cancelled`.

## What V0 Does Not Guarantee

- No embedded preview. Capture goes through the full-screen system camera UI.
- No real file path: `PhotoFile.path` is a `memory://` placeholder and
  `base64` carries the image (3–8 MB per 12 MP photo across the bridge).
  V1 replaces this with a native temp file and a real path.
- No Android native module yet (`android/` is a placeholder). The install
  check reports `native-module-missing` on Android hosts.
- No video recording, zoom, torch, or tap-to-focus.
- The legacy `capture(options, callback)` native method is supported as a
  fallback for early experimental hosts, but is deprecated and will be
  removed before `0.2.0`; implement `capturePhoto` instead.

## V0 Exit Criteria

V0 is superseded when V1's `camera-view` reaches its MVP acceptance criteria
(see V1.md). Until then, V0 changes must stay backward-compatible within the
`0.1.x` line: no removals or behavior changes to the surface above without a
minor version bump and a note in this file.
