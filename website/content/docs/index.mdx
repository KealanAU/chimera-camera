Chimera Camera is a native camera library for [Lynx](https://lynxjs.org), built off the
work in [`react-native-vision-camera`](https://github.com/mrousavy/react-native-vision-camera).
It targets Lynx directly instead of wrapping React Native, which is why the public API is
plain TypeScript that any JS framework can drive.

> [!WARNING]
> **Pre-alpha.** The package publishes as `0.0.x` while the surface settles. Any release can
> break you — read [Platform support](#platform-support) before depending on this. The first
> real launch will be `1.0.0`.

## What you get

- Photo capture, through an embedded preview or the system camera
- Video recording with optional audio *(written, unverified)*
- Zoom, torch, tap-to-focus, and exposure bias *(written, unverified)*
- Front/back switching, `resizeMode`, and live `active` toggling
- Photo-library picking and saving back to the library
- Camera and microphone permission checks and requests
- Framework-neutral: React, Vue, Svelte, or plain TypeScript, all unwrapped
- A [mock adapter](./mock), so app flows can be built before any native wiring exists
- [Install diagnostics](./install-diagnostics) that name the native step you are missing
- [File paths across the bridge](./output-transport) rather than multi-megabyte base64 payloads

## Two surfaces

Every operation belongs to exactly one of two surfaces, and the split is part of the contract.

| Surface | Created by | Owns |
| ------- | ---------- | ---- |
| [Module](./camera-module) | `createCameraModule()` → `CameraModuleClient` | Stateless one-shots that need no rendered view: permissions, device discovery, system-camera capture, photo picking, saving to the library. |
| [Session](./camera-view) | `createCameraViewHandle()` → `CameraViewHandle` | Controls tied to a live `<camera-view>`: view capture, recording, focus, zoom, torch, exposure, and `ping()`. |

Permissions and device enumeration are app-level concerns; preview, focus, zoom, capture, and
recording depend on an active camera session. Keeping them apart means a permission check never
needs a mounted element, and a capture never needs a permission round-trip it did not ask for.

## A complete flow

```tsx
<camera-view id="camera" active={true} facing="back" bindready={onReady} />
```

```ts
import { createCameraModule, createCameraViewHandle } from '@vyui/camera'

const module = createCameraModule()
await module.requestCameraPermission()

const camera = createCameraViewHandle('#camera')
const photo = await camera.capturePhoto({ flash: 'auto' })

console.log(photo.path)            // display with `file://${photo.path}`
await module.saveToLibrary(photo)  // and/or keep it
```

Two runnable demos drive that same core from different frameworks: `example/react` and
`example/vue`.

## Platform support

| Platform | Status | Verified |
| -------- | ------ | -------- |
| iOS | Alpha | Device-proven on a physical iPhone: preview, photo capture, front/back switch, close/reopen. Recording and session controls are written but unverified. |
| Android | Experimental | Written to the same [native contract](./native-contract) as device-proven iOS and believed to work, but never compiled or run on any device or emulator. |
| Mock | Stable | Framework-neutral JS double for all hosts. |

Minimums: **iOS 15** deployment target, **Android 7.0** (`minSdk` 24).

Android ships as experimental on purpose. The Kotlin/CameraX surface mirrors the native contract
and the device-proven iOS behavior, which is fair reason to expect it to work, but nobody has
confirmed that on hardware yet. Treat Android as unsupported until it passes device acceptance.

## Not in scope

Framework wrapper components or hooks, web support, frame processors, Skia integration, barcode
scanning, and depth/RAW/HDR tuning beyond default platform behavior. React Native, Nitro Modules,
and JSI are not dependencies and will not become ones.
