Chimera Camera should use VisionCamera as a reference and selective port source. It should not become a long-lived React Native compatibility fork.

## Rules

- Keep the public API Lynx-native and framework-neutral.
- Do not add React Native, Nitro, JSI, React hooks, or `react-native-*` runtime dependencies for V1.
- Preserve MIT license attribution for copied or substantially derived source.
- Port camera engine ideas behind local Lynx bridge types.
- Prefer small, reviewable native slices that preserve the V1 surface contract.

## High-value iOS references

- `HybridCameraSession.swift`
- `HybridPreviewView.swift`
- `HybridCameraPhotoOutput.swift`
- `CapturePhotoDelegate.swift`
- `HybridCameraVideoOutput.swift`

## High-value Android references

- `HybridCameraSession.kt`
- `ConstraintResolver.kt`
- `HybridPreviewView.kt`
- `HybridPhotoOutput.kt`
- `HybridVideoOutput.kt`
- `HybridVideoRecorder.kt`

## Replacement work

When porting from upstream, replace React Native and Nitro-facing types with local Lynx-native equivalents.

The useful implementation shape is native camera behavior. The public surface, lifecycle hooks, event pipeline, and dependency graph should belong to Chimera Camera.
