The native bridge should expose the same JavaScript surface on Android and iOS while using the normal camera stack on each platform.

## Android

Android targets:

- Register `camera-view` through Lynx `Behavior` and `LynxUI`.
- Expose view methods with `@LynxUIMethod`.
- Emit view events with `LynxDetailEvent`.
- Use CameraX for camera behavior.
- Wrap `androidx.camera.view.PreviewView` when preview starts.

The bridge spike can use a placeholder view before `PreviewView` is connected.

## iOS

iOS targets:

- Register `camera-view` through Lynx `LynxUI` registration.
- Expose view methods through `LYNX_UI_METHOD`.
- Emit detail or custom events through the Lynx iOS event pipeline.
- Use AVFoundation for camera behavior.
- Render preview with `AVCaptureVideoPreviewLayer`.

The bridge spike can render a placeholder layer or view before AVFoundation preview is connected.

## Shared contract

Both platforms should preserve:

- The `camera-view` tag name.
- The `CameraViewProps` prop names.
- The `CameraViewMethods` method names and return values.
- The event names and `detail` payload shapes.
- Stable error codes.

Native implementation details can differ, but JavaScript should not need platform-specific branching for the V1 surface.
