# 0.3 — Recording and controls on the view (M5)

Release checklist. Builds on both platforms having a working `camera-view`
([0.2.md](0.2.md)).

**Theme:** the view session grows from photo capture to the full control
surface `CameraViewMethods` promises.

## Done

- [x] iOS view-session `capturePhoto()`: `AVCapturePhotoOutput` JPEG to a
      temp file, `{ path, width, height, orientation, mime }`, `base64`
      opt-in (landed early, in the 0.1 line).

## Remaining

- [ ] `startRecording(options)` / `stopRecording()` returning a real
      `VideoFile` path — iOS (`AVCaptureMovieFileOutput`) and Android
      (CameraX `VideoCapture`).
- [ ] `enableAudio` honored, microphone permission checked before recording.
- [ ] `onRecordingStarted` / `onRecordingFinished` events.
- [ ] `setZoom(value)` clamped to device min/max.
- [ ] `setTorch(mode)` with a predictable unsupported-control error.
- [ ] `focusAtPoint(point)` where supported, predictable error where not.
- [ ] Android view-session `capturePhoto()` to match iOS.
- [ ] Capture-time `filter` option (`'none' | 'mono' | 'noir' | 'sepia' |
      'chrome'`): built-in `CIFilter` photo effects applied at encode on iOS,
      `ColorMatrixColorFilter` redraw on Android — stills only, ~10 lines in
      each existing encode path. Live filtered preview is out: it means
      replacing the preview layer with per-frame rendering (frame processors,
      an explicit V1 non-goal); a host-side tint overlay fakes simple looks.
- [ ] Portrait-lock ponytail in iOS view capture revisited if a landscape
      host consumes this (`ios/ChimeraCameraView.m` orientation note).
